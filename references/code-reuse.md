# 代码复用审查参考

检查是否有重复代码或遗漏的现有工具函数。复用优先于重写。

## 检查清单

### 重复实现

- 新写的函数/方法是否与项目中已有功能重复
- 相似逻辑是否可以通过参数化统一为一个函数
- 复制粘贴后略作修改的代码块是否存在

### 遗漏的现有工具

- 手动实现的字符串处理是否可以用现有 utility 替代
- 手动路径拼接是否可以用路径工具替代
- 手动类型检查是否可以用已有的类型守卫替代
- 手动环境检测是否可以用配置模块替代

### 可提取的公共逻辑

- 多处使用的常量或配置是否应提取为共享常量
- 重复的验证逻辑是否应提取为验证函数
- 重复的数据转换是否应提取为转换函数

### 错误的复用

- 是否误用了不相关的工具函数（语义不匹配）
- 是否过度抽象导致简单问题复杂化

## 搜索范围

| 目录 | 内容 |
|------|------|
| `src/utils/` 或 `src/lib/` | 通用工具函数 |
| `src/helpers/` | 辅助函数 |
| `src/shared/` | 共享模块 |
| `src/common/` | 公共组件 |
| 目标文件相邻目录 | 领域相关的工具函数 |

搜索关键词：新写代码中的核心操作（字符串处理、路径操作、类型转换、数据格式化等）。

## 严重级别判定

| 级别 | 典型场景 |
|------|---------|
| **blocking** | 大段代码复制粘贴且存在 bug 风险；重复实现与原实现行为不一致 |
| **major** | 手动实现了项目中已有的 utility 功能；明显的复制粘贴变体 |
| **minor** | 可以复用但不复用的影响较小；提取公共逻辑的收益有限 |

## 审查方法

1. 读取 implementer-log.md 获取新建和修改的文件列表
2. 对每个新写的函数，搜索项目中是否有相似功能的已有实现
3. 对手动实现的基础操作（字符串、路径、类型等），检查 utils 目录是否有替代
4. 检查是否有相邻文件中的重复逻辑
5. 记录发现，附上已有函数的位置和建议的替换方式
