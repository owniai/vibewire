# 设计符合性审查参考

对照 design.md 检查实现是否偏离设计意图。关注实质偏离，不纠结代码风格。

## 检查清单

### 接口签名

- 函数/方法签名是否与 design.md 一致（参数名、类型、返回值）
- 公共 API 是否暴露了设计中未规划的接口
- 设计中规划的接口是否缺失

### 模块划分

- 文件/目录结构是否与 design.md 描述一致
- 模块职责是否与设计中的划分一致
- 是否有设计之外的模块或文件

### 数据流

- 数据在模块间的传递方式是否与设计一致
- 数据结构/类型是否与设计一致
- 数据转换和处理流程是否偏离设计

### 错误处理策略

- 错误处理方式是否与设计一致（异常 vs 错误码 vs Result 类型）
- 错误分类和传播方式是否符合设计
- 边界情况的错误处理是否遗漏

### 状态管理

- 状态存储方式是否与设计一致（数据库、内存、文件等）
- 状态生命周期是否与设计一致
- 并发/竞态处理是否与设计一致

### 依赖关系

- 引入的依赖是否在设计中规划过
- 是否遗漏了设计中指定的依赖
- 依赖的使用方式是否与设计意图一致

## 严重级别判定

| 级别 | 典型场景 |
|------|---------|
| **blocking** | 接口签名偏离导致调用方不兼容；错误处理方式与设计矛盾；模块职责偏离设计 |
| **major** | 数据结构偏离但不影响功能正确性；缺少设计中的非关键接口 |
| **minor** | 命名与设计略有不同但语义一致；实现细节与设计描述有细微差异 |

## 审查方法

1. 读取 design.md 中的架构概览和模块划分
2. 对照实际文件结构，检查模块是否一一对应
3. 逐个检查 design.md 中描述的接口，对比实现中的接口签名
4. 检查错误处理和数据流是否与设计描述匹配
5. 记录偏离，附上 design.md 中的原文引用和实际代码的差异
