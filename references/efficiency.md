# 效率审查参考

检查性能问题、不必要的工作和资源浪费。关注可观测的效率问题，不做过早优化。

## 检查清单

### 不必要的工作

- 是否有冗余计算（同一结果被多次计算）
- 是否有重复的文件读取（同一文件被多次读取）
- 是否有重复的网络/API 调用
- 是否有 N+1 查询模式（循环内逐个查询）

### 遗漏的并发

- 独立的操作是否被串行执行，可以并行
- 文件读写是否有不必要的等待
- API 调用是否可以批量处理

### 热路径膨胀

- 启动路径上是否添加了不必要的阻塞工作
- 每次请求/渲染是否执行了可以缓存或延迟的工作
- 初始化是否做了运行时不需要的准备

### 无效更新

- 循环/定时器/事件处理器中是否有无条件的状态更新
- 状态更新是否有变更检测（值未变时跳过）
- 包装函数是否正确处理"无变更"信号

### 不必要的存在性检查

- 操作前是否预先检查文件/资源存在性（TOCTOU 反模式）
- 应该直接操作并处理错误，而非先检查再操作

### 内存问题

- 是否有无限增长的数据结构
- 是否有未清理的事件监听器
- 是否有未关闭的资源（文件句柄、连接等）
- 大数据集是否可以流式处理

### 过于宽泛的操作

- 是否读取了整个文件但只需要部分内容
- 是否加载了所有数据但只需要过滤后的子集
- 查询是否缺少筛选条件导致返回过多数据

## 严重级别判定

| 级别 | 典型场景 |
|------|---------|
| **blocking** | N+1 查询导致生产级性能问题；资源泄漏导致服务不稳定；无限增长导致内存溢出 |
| **major** | 重复计算/查询有明显的性能影响；遗漏的并发机会导致不必要的等待；TOCTOU 反模式 |
| **minor** | 轻微的冗余操作；可优化但影响不大的代码；理论上的内存风险 |

## 审查方法

1. 读取变更的代码文件
2. 重点检查循环、递归和 I/O 操作
3. 搜索数据库查询、文件读写、API 调用等 I/O 密集操作
4. 检查是否有共享状态导致的并发问题
5. 对可疑的效率问题评估实际影响，不做过度优化
6. 记录发现，附上具体行号和预估影响
